# Deterministic model evaluation

`precision_core` evaluates an immutable `DocumentRecord` before any geometry worker receives a request. The evaluator has no geometry-kernel or process dependency. It validates the registered worker feature types and returns a stable topological plan, preserving original document order between equally ready features.

The current registry accepts `box`, `cylinder`, `extrude`, `union`, `cut`, `intersection`, `translate`, `rotate`, `fillet`, `validate`, and `tessellate`. Each type has an exact parameter shape, finite numeric values, bounded coordinates, and explicit input arity. Version 1 box records may include `origin`; cylinder records may include `origin` and `axis`. Values use the document's explicit `mm` or `in` unit record. Unsupported feature types and invalid parameters fail before dispatch.

Suppression is an evaluation state, not a missing result. A directly suppressed feature suppresses every transitive dependent and records its direct suppression source. The controller schedules only `Ready` entries, so no dependent worker request is constructed with a missing BREP.

The plan contains no worker output cache. Geometry results remain revision-bound controller state. A candidate keeps its document identity and revision through worker dispatch and commits only when those values still match the current document. Failed validation or worker execution discards the candidate and preserves the last committed record.

After a successful commit, the workspace projects `meshParts` from committed terminal feature results only. Each part has `bodyId`, `vertices`, `indices`, and `normals`. A terminal result is not consumed by another ready feature, so independent bodies are shown together while boolean operands are not duplicated. Selecting a nonterminal source shows its single-result preview; selecting a terminal result keeps the terminal scene. The legacy selected-result `meshVertices` and `meshIndices` fields remain available with `meshNormals` added alongside them. Pending and failed candidates never replace the committed scene.

An unknown nonempty selection request is a no-op. An empty selection intentionally clears the selected-result mesh, normals, measurements, and `selectedBody`, while terminal `meshParts` remain visible. A successful edit retains its selected ready feature. A newly added terminal feature becomes selected. Opening a document and losing the active feature through suppression or removal select the deterministic last terminal result, or clear the selection when no terminal result remains. These fallback rules apply only after a successful structural commit.
