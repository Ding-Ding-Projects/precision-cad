# Local Git project history

`precision_history` is a local-only Qt Core adapter for an explicitly selected CAD project directory. `initialize` attaches only when Git reports that exact root. `createProjectRepository` separately creates metadata for an existing empty directory or one containing only validated native documents. It refuses directories already belonging to a parent repository, unrelated files, and existing metadata. Initialization stages metadata in a temporary child and renames it into place without replacing existing metadata.

The adapter invokes the supplied Git executable with argument arrays, removes inherited Git environment overrides, disables interactive credential requests and optional index refreshing, and makes no network calls. Commands have a 10-second deadline and retain at most 8 MiB per output channel, drained in bounded chunks. This limits captured output, not the operating system pipe or Qt internal allocation. Native reads are bounded before and during reading; core parsing additionally enforces its 16 MiB limit. Explicit paths must identify `.pcad` or `.cad.json` files within the chosen project, without traversal, `.git` components, alternate stream syntax, or symlink ancestors.

## Selected-file commit transaction

The service acquires the standard exclusive `index.lock` before reading or copying the index. Git processes respecting that lock cannot introduce staged changes during the transaction. Existing staged changes are refused against the captured parent. Only selected native files are added to a private index, and the exact staged bytes are validated through `precision_core`. Unrelated working files are neither included nor overwritten. An unchanged tree is a successful no-op.

`write-tree` and `commit-tree` construct an immutable candidate whose parent is the captured commit. `update-ref` publishes it with an exact old-object compare-and-swap. A concurrent commit therefore causes refusal, rather than silently rebuilding on a newer parent or discarding its tree. The prepared index is written through `QSaveFile` while the standard index lock remains reserved, after checking the active symbolic target and commit. Successful first and subsequent commits leave the primary index coherent with their commit.

These plumbing operations intentionally do **not** execute configured commit or reference-transaction hooks and do not sign commits. A user requiring those hooks must use their regular Git client. Filters configured for `git add` still apply, so the resulting staged native bytes are validated too. The service uses the caller-supplied local author identity and does not configure a global identity.

Failures before reference publication leave the original index and working bytes unchanged. Unreferenced candidate objects may remain in Git. `commit-publication-unconfirmed` includes `HistoryError.recoverableCommit` when publication failed or cannot be confirmed. `commit-published-index-pending` includes the exact published commit when index replacement fails or HEAD moves before reconciliation. Neither partial result is reported as success; callers must present it and re-inspect history before another operation. No broad reset is attempted. Git ref publication and index replacement are separate filesystem transactions: a process crash between them requires index reconciliation, and this API is not a power-loss journal. Direct filesystem writes or ref-only changes by external programs that ignore normal index coordination are outside its exclusion mechanism.

## Comparison and protected restore

Semantic comparison validates the raw input bytes before JSON normalization, so duplicate keys and ambiguous numeric records cannot disappear during parsing. Restore preview validates active and historical raw records, resolves a commit once, and reads that exact commit. It binds SHA-256 digests of both byte sequences.

Apply acquires the document lock and rechecks both bound inputs. It requires matching document identity, advances the active revision by one, refuses the maximum revision, and validates the replacement. Before atomic replacement it writes the exact previous bytes to an exclusive sibling file. Existing preservation files and forged paths outside that sibling naming boundary are refused. A stale preview does not change the model. The advisory document lock coordinates participating writers; callers must not concurrently write the same model without that protocol.

## Verification

`tests/history/local_history_service_test.cpp` uses real disposable Git repositories and an executable adapter for deterministic interleavings. Coverage includes first and repeated index coherence, no-op commits, exact failure preservation, unrelated stage contention, concurrent HEAD publication, explicit partial publication, primary lock ownership, intentionally disabled hooks, invalid raw records, stale previews, preserved bytes, revision bounds, path boundaries, new-project creation, and stdout/stderr flooding. It does not use user documents or credentials. Standalone build: configure `src/history` with Qt 6.8 Core/Test and a C++20 compiler, build, then run CTest.
