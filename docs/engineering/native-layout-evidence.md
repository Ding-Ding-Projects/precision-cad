# Native Qt Quick layout evidence

This application has no browser DOM or CSS layout engine. Its layout equivalent is measured with `QQuickItem::mapRectToScene`, `childrenRect`, implicit sizes, effective visibility, opacity and clipping. Browser `getBoundingClientRect` and CDP ownership assertions do not apply and are not fabricated.

Set `PRECISION_LAYOUT_AUDIT=1` only for a run with an explicit isolated `--profile-directory`. The built application writes a bounded, atomic `layout-audit.json` there. The diagnostic records allowlisted component names and geometry only; it never serializes text, documents, private vocabulary, settings or selected file paths. Production runs without that explicit diagnostic flag write no layout file.

The same explicit audit run establishes a version-2 `native-diagnostics-run.json` descriptor before workspace or QML construction. It binds a fresh random `runId`, the exact 40-character lowercase source commit, process id, UTC start time, and a relative receipt filename. The receipt lives in a newly created `native-diagnostics-<runId>/native-diagnostics.json` directory whose Windows ACL permits only the current user and SYSTEM. Existing profile permissions are never changed. Every drive root, network/device path, alternate stream, and existing reparse ancestor is rejected. Invalid source provenance, an unavailable private directory, or an unsuccessful initial receipt/descriptor write prevents audit startup with exit code 2. An older descriptor can remain when replacement fails, so consumers must independently match the newly launched process and expected run identity; existence alone never establishes a successful start.

Receipts contain only that identity, UTC freshness times, a monotonically increasing heartbeat sequence, Qt warning/critical/fatal and QML-warning counts, and completion flags. No message text, categories, source locations, document content, settings, history, passwords, or selected paths are retained. Counts saturate at the largest exactly representable JSON integer, 9,007,199,254,740,991; overflow sets `droppedEvents` and permanently prevents completion. Heartbeats are atomic counts-so-far snapshots with `sealed=false` and `countsComplete=false`, including when all counters are zero.

Normal shutdown destroys the QML engine, workspace, and preference objects first, then drains the logging counter handoff and atomically writes the final snapshot. Only that successful finalization sets both `sealed=true` and `countsComplete=true`. A warning immediately before destruction is included without requiring another event-loop turn. A write failure permanently invalidates that run; if a later write succeeds it still cannot seal. Failed finalization returns exit code 2. Fatal logging, process crashes, forced termination, and power loss do not provide a finalization guarantee and leave missing or unsealed evidence. A previously written active snapshot remains explicitly incomplete when its replacement fails. Promotion must require both true flags, schema version 2, exact matching run id/process id/source commit/start time, and an independently observed normal process exit. It must not promote a live heartbeat or a force-killed capture.

The message callback uses only bounded counters under a standard C++ mutex. It performs no Qt queueing, synchronization, allocation, or file I/O. One process-lifetime dispatcher keeps any previously installed custom handler in its forwarding chain even after collection ends; later forwarding handlers may safely retain the dispatcher. Reentrant forwarding is bounded. With no prior custom handler, explicit audit mode retains counts only rather than raw default log output. Normal runs install no hook. Audit collection requires later custom handlers to forward to the installed handler; replacing it with a non-forwarding handler is unsupported and invalidates evidence because Qt provides no non-mutating API to inspect its handler chain. The audited lifetime ends at the final counter cut, before destruction of the process-level application object. The scope and normal-exit requirement prevent that boundary from being mistaken for whole-process crash diagnostics.

The focused `native-diagnostics` regression covers immediate engine/tail warnings, QML counts and text omission, startup refusal with a preseeded locked old descriptor, immutable unsealed active snapshots, failed final writes, a real fatal child, concurrent/reentrant callback teardown, forwarding after deactivation and into a second run, exact JSON counter overflow, all reported drive roots, and a real Windows directory junction.

Bind the native version-1 measurement to the exact process/window discovered on the owned hidden desktop, source commit, runtime receipt and genuine window capture. This is a native Qt receipt, not a claimed pass of the browser-specific CSS/CDP validator. Both raw captures and measured native geometry must support a layout conclusion.

## Workspace geometry regression

The documented and enforced minimum client area is 800 by 600. The QML geometry regression exercises that minimum, the 1024 by 700 working size, and the 1280 by 820 default. For English, Cantonese, and bilingual language modes in both light and dark themes, it proves the `ToolBar` height equals the visible `toolbarFlow` implicit height plus the native vertical insets, all 13 toolbar flow controls remain within that measured boundary, the workspace starts immediately below it with a usable height, and the model help remains reachable. Inspector children including the version provenance and unfinished-feature notice do not exceed the inspector column width. The high-scale bilingual tone-five tuple obtains the `ScrollView` content item, verifies its `contentY` and `contentHeight` properties, and moves that real item to its measured maximum when the actual surface overflows. If the production tuple does not overflow, an isolated native `ScrollView` fixture deliberately constrains its scrollport and proves the same real-item scroll operation with measured overflow. Deliberate old toolbar and non-scrollable-inspector QML fixtures are expected to fail their matching contracts before the real surface passes them. These are native `QQuickItem` measurements from the QML scene, not browser geometry claims.
